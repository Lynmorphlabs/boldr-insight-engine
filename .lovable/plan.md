
# Make `/intelligence` real (for the demo)

Right now the page is 100% hand-authored seed from `src/data.ts`. For a judge demo, the cheapest "this is actually working" win has two parts: compute theme clusters from the real ticket data, and generate the Monthly Brief with Gemini from those themes + external quotes. Keeps the same visual layout, just swaps the data source.

## What changes (user-visible)

1. **Theme cluster cards** — counts, dominant persona, and trend arrows are computed live from `tickets` (grouped by `lane`/`theme`). No more hardcoded numbers.
2. **Persona distribution** — already computed from tickets, leave as-is.
3. **Monthly Marketing Brief** — generated by Gemini (Lovable AI, no API key needed) from:
   - The top 5 live theme clusters
   - A sample of recent `external_quotes` (Reddit + Firecrawl)
   - The KB gaps (`isKnowledgeGap` tickets) — to surface "what customers ask that's not on product pages"
   
   Output: title, intro, and 3–5 brief items (theme, personas, gap, recommended action). Cached in a new `monthly_briefs` table so it doesn't regenerate on every page load; a "Regenerate brief" button on the page triggers a fresh run.

## Why this approach

- **Believable**: every number on the page traces back to either a ticket row or a Gemini call grounded in real data. Judges can point at any card and you can show the source.
- **Cheap to build**: ~1 server function + 1 small table. No new external API. Reuses Lovable AI (already wired).
- **Fast demo**: brief is cached, so the page loads instantly; the "Regenerate" button is the live-AI moment.

## Technical sketch (for reference)

```text
src/lib/intelligence.functions.ts   ← new
  - getThemeClusters()        // groups tickets by lane, computes counts +
                              //   dominant persona + trend (this wk vs last)
  - getLatestBrief()          // reads monthly_briefs, returns most recent
  - regenerateBrief()         // calls Gemini via Lovable AI, inserts row

src/lib/intelligence.server.ts      ← new (Gemini prompt + classification)

migration: monthly_briefs table
  id uuid pk, month text, title text, intro text,
  items jsonb, generated_at timestamptz default now()
  RLS: public read, server-only insert

src/routes/intelligence.tsx
  - replace `themes` import with useQuery(getThemeClusters)
  - replace `monthlyBrief` with useQuery(getLatestBrief)
  - add "Regenerate brief" button → useMutation(regenerateBrief)
  - auto-trigger regenerate on first load if monthly_briefs is empty
    (same pattern as the external sentiment auto-sync on /benchmark)
```

Gemini call uses `google/gemini-3-flash-preview` with `Output.object` schema so the brief JSON is guaranteed-shape.
